# Аутрич: барбершопы Барселоны

Инструмент для холодного поиска первых клиентов. Живёт рядом с сайтом, потому
что тянет из него цены, кейсы и ссылки с UTM — одно место правды, а не второй
список цен, который разъедется с первым через месяц.

**Ниша №1:** барбершопы и мужские парикмахерские Барселоны.
**Канал №1:** Instagram DM. WhatsApp — второй. Личный обход — третий.
**Оффер:** макет главной бесплатно за 24 часа → сайт 450 €.
**Первым трём:** 300 € вместо 450 в обмен на отзыв и право показать сайт в кейсах.

---

## Быстрый старт

```bash
npm run outreach                 # список команд
npm run outreach today           # что делать сегодня
npm run outreach -- msg <id>     # текст сообщения
```

`--` обязательно перед флагами: без него npm заберёт `--hook` себе, и он не
дойдёт до скрипта. Чтобы не писать это каждый раз:

```bash
alias o='node outreach/cli.mjs'   # дальше просто: o today, o msg <id>
```

Данные лежат в `outreach/data/leads.json`. Файл **не коммитится** — репозиторий
публичный, а внутри телефоны бизнесов и заметки вроде «сайт не открывается»,
написанные для себя, а не для них. Держи его в бэкапе (iCloud, Dropbox, приватный
gist). Сделаешь репозиторий приватным — блок `outreach` в `.gitignore` можно
снять, и список поедет вместе с кодом.

## Дневной цикл

```
harvest → audit → qualify → msg → touch → follow-up → won
```

**1. Собрать лидов** (раз в 1–2 недели, автоматом)

```bash
npm run outreach:harvest -- --only-no-website
npm run outreach -- import outreach/data/harvest-2026-08-10.json
```

Ходит в Google Places по 25 районам Барселоны и приносит название, адрес,
телефон, рейтинг, число отзывов и — главное — **есть ли у них сайт**. Кто без
сайта, тот в первую очередь. Нужен `GOOGLE_PLACES_API_KEY` в `.env.local` —
как его завести, см. ниже.

### Ключ Google Places — по шагам

1. **Проект.** [console.cloud.google.com](https://console.cloud.google.com/) →
   селектор проектов вверху → *New Project* → имя (`outreach`) → *Create*.
   Нужен только гугл-аккаунт.
2. **Карта.** *Billing* → *Link a billing account* → создать платёжный аккаунт.
   Карта обязательна даже ради бесплатного лимита: без привязанного платёжного
   аккаунта Maps отвечает **один раз в сутки** — не блокирует, а душит, и это
   легко принять за поломку скрипта. Аккаунт должен быть привязан именно
   к этому проекту. Новым клиентам Google Cloud дают 300 $ на 90 дней.
3. **Включить API.** *APIs & Services* → *Library* → **Places API (New)** →
   *Enable*. Именно New: старый «Places API» — другой продукт, и в новых
   проектах его уже нельзя включить. После нажатия подожди пару минут —
   включение расходится по серверам не мгновенно.
4. **Ключ.** *APIs & Services* → *Credentials* → *Create credentials* →
   *API key*. Скопировать (начинается с `AIza`, ~39 символов).
5. **Ограничить ключ — не пропускать этот шаг.** На той же странице открыть
   ключ:
   - *API restrictions* → **Restrict key** → отметить только Places API (New).
     Без этого ключ автоматически получает доступ к любому API, который ты
     когда-нибудь включишь в этом проекте, — включая платные ИИ-эндпоинты.
   - *Application restrictions* → **IP addresses** (в консоли подписано
     «web servers, cron jobs»), вставить свой публичный адрес:
     `curl -s https://api.ipify.org`. Провайдер сменит адрес — скрипт получит
     403, вернёшься и поправишь за минуту.
   - **Не ставить HTTP referrers.** Node не шлёт заголовок Referer, и Google
     такой ключ для веб-сервисных API просто отклоняет.
6. **Положить в проект.** В `.env.local`: `GOOGLE_PLACES_API_KEY=AIza...`
   Файл уже в `.gitignore`. Ключ читает только этот скрипт, на сайт он
   не попадает.
7. **Потолок расходов.** Привязка карты **снимает** суточный лимит, который
   до этого тебя защищал. *APIs & Services* → *Quotas* → выставить дневной
   потолок запросов для Places API. Бюджетные уведомления в Billing только
   пишут письмо, тратить не мешают, — потолок ставится здесь.

**Сколько это стоит.** Маска полей просит `websiteUri`, телефон, рейтинг и
число отзывов — это самый дорогой тариф Text Search (Enterprise, 35 $ за 1000
запросов). Дешевле не выйдет: `websiteUri` и есть признак «сайта нет», ради
которого всё затевалось. Но объём крошечный: 25 районов × 2 формулировки, по
3 страницы максимум — полный проход по Барселоне это 50–150 запросов при
бесплатных **1000 в месяц**. Проход бесплатен, и до первого счёта нужно
сделать их семь штук за один календарный месяц. Запрос, вернувший пустоту,
тоже считается — не гоняй скрипт вхолостую.

**Про хранение.** Условия Maps Platform разрешают хранить бессрочно только
идентификаторы мест; название, адрес и телефон формально положено запрашивать
заново, а не держать в своей базе месяцами. Для личного рабочего списка это
формальность, но знать о ней стоит — и это ещё один довод держать `leads.json`
приватным. По-хорошему Places нужен один раз, чтобы найти лида, а дальше
рабочая запись — это твои собственные наблюдения: Instagram, хук, статусы.

**2. Разобрать тех, у кого сайт есть** (автоматом)

```bash
npm run outreach:audit
```

Открывает каждый сайт и ищет, к чему придраться по делу: не открывается, нет
HTTPS, нет `viewport` (на телефоне всё уезжает), нет цен, грузится восемь
секунд, в подвале 2019 год. Заодно вытаскивает Instagram из ссылок на сайте.
Каждая находка ложится в заметки лида и становится черновиком повода написать.

Если аудит сказал «сайт не открылся» — **открой глазами**. Упасть мог твой
интернет, а начинать знакомство с неправды нельзя.

**3. Проверить и подготовить** (руками, ~2 минуты на лида)

Открой Instagram и карты. Смотри на три вещи:

- Аккаунт живой? Последний пост в этом месяце. Мёртвый аккаунт — `skip`.
- Это независимый барбершоп, а не сеть? У сети есть маркетолог и подрядчик.
- Кто отвечает в директ? Если в шапке имя владельца — пиши по имени.

```bash
npm run outreach -- qualify <id> --instagram handle --priority 1
npm run outreach -- hook <id> "одно настоящее наблюдение по-испански"
```

**Хук — это вся работа.** Не «делаю сайты для барбершопов», а «зашёл к вам в
профиль: цены только в закреплённых сторис, и в директ вы их пишете по десять
раз в день». Шаблонный хук система подставит сама и честно предупредит, что он
шаблонный. Отклик на шаблоне — единицы процентов; на конкретном наблюдении —
кратно выше, и это единственное, что стоит времени в этой работе.

**4. Написать**

```bash
npm run outreach -- msg <id> --copy     # текст в буфер
npm run outreach -- touch <id>          # отправил → записать, назначить follow-up
```

**5. Ответили «покажи» — макет за час, а не за сутки**

```bash
npm run outreach:fonts                                  # один раз на машину
npm run outreach:mockup -- --lead <id>                  # каркас из данных лида
# правишь outreach/mockups/<id>.json — 5 минут по их Instagram
npm run outreach:mockup -- --lead <id> --shot           # HTML + два скриншота
```

Собирает готовую главную их барбершопа: на первом экране не слоган, а доска
свободных сил с именем мастера — то же, на чём построен кейс Strop. Трекер уже
знает название, район, адрес и телефон, поэтому руками остаётся то, что за тебя
никто не сделает: настоящие цены, имена мастеров и одна строка про то, чем этот
барбершоп отличается от соседнего.

Три темы под их картинку в профиле: `brass` (дерево и латунь), `bone` (светлая,
плитка и минимализм), `ember` (чёрное с горячим красным, фейды). Тема меняется
одним словом в конфиге.

Пока цены черновые, страница честно пишет: «Estos precios son de ejemplo — dime
los tuyos y te los cambio en un momento». Это не отговорка, а повод ответить:
владельцу проще прислать свой прайс, чем промолчать. Заполнил настоящие — убрал
`"pricesAreDraft": true`, и полоска исчезла.

**В Instagram первым уходит скриншот, не ссылка.** Картинку в директе
открывают, ссылку от незнакомого — часто нет. Ссылку даёшь, когда попросят:
`npx vercel deploy outreach/mockups/<id>`.

Посмотреть, каким должен получиться заполненный макет:

```bash
npm run outreach:mockup -- --config outreach/mockup/demo.json --shot
```

Шрифты (Bricolage Grotesque + IBM Plex Sans, оба OFL) вшиваются в файл — макет
открывается без интернета и выглядит одинаково у всех. Без кэша страница возьмёт
их из Google Fonts и тоже отрисуется.

**6. Follow-up** — `npm run outreach today` сам поднимает тех, кому пора.

Ритм: 1-е касание → +3 дня → +5 дней → +10 дней → всё. Четыре касания и стоп.
Пятое не приносит клиентов, приносит блокировку.

## Лимиты Instagram (не нарушать)

Инстаграм банит за холодные DM охотнее, чем за что угодно ещё, и потерять
аккаунт на старте — потерять канал целиком.

- **10–15 первых DM в день** с аккаунта, который до этого только постил. Не 50.
- Растягивать по дню, а не двадцать штук за десять минут.
- Перед первым DM — зайти в профиль, посмотреть пару постов, поставить лайк.
  Заход из ниоткуда в директ выглядит ровно как бот, потому что так делает бот.
- Никакой ссылки в первом сообщении. Первый DM от незнакомца со ссылкой уходит
  в «Запросы» и не читается. Ссылка — во втором, когда переписка уже есть.
- Одинаковый текст двадцати аккаунтам подряд — самый быстрый способ поймать
  ограничение. Хук на каждого лида решает и эту задачу тоже.
- **Автоматизировать отправку DM нельзя.** Любой сервис массовой рассылки в
  инстаграме — это бан аккаунта, вопрос недель. Отправка руками, всё остальное —
  автоматом.

WhatsApp: писать только по номеру, который бизнес сам опубликовал в Google
Maps, и не больше 10–15 в день с обычного номера. Это второй канал, не первый.

## Скидка первым трём

Место занимает **закрытая сделка по 300 €**, а не отправленное сообщение.
Считает система, число подставляется в испанский текст само — «Quedan dos»
всегда правда.

```bash
npm run outreach -- status <id> won                 # 300 €, занимает место
npm run outreach -- status <id> won --full-price    # 450 €, место остаётся
```

Скидку **не даём первым сообщением.** Открыть разговор ценой — значит продавать
скидку вместо сайта, и когда клиент засомневается, отдать будет уже нечего.
Скидка идёт третьим касанием либо в ту секунду, когда спросили «сколько стоит».

Условие проговариваем **до начала работы**, а не после запуска: отзыв в две
строки и разрешение показать сайт в портфолио. После запуска просить неудобно —
и получаешь «конечно-конечно» вместо отзыва.

Что просить в отзыв: не «всё понравилось», а что изменилось. «Раньше цены
писали в директ по двадцать раз в день, теперь их видно на сайте» — такой отзыв
продаёт следующему барберу. Разрешение на кейс — на сайт, скриншоты и название.

## Что отвечать

```bash
npm run outreach replies
```

Шесть ответов, которые реально приходят, с готовым текстом и пометкой, почему
он такой. Коротко:

- **«Сколько стоит»** — называть сразу. Уклончивый ответ убивает сделку быстрее,
  чем цена.
- **«У меня уже есть сайт»** — не спорить, показать одну конкретную вещь и
  предложить сравнить с бесплатным макетом.
- **«Пришли информацию»** — это вежливое «нет». Не слать PDF, вернуть разговор
  к макету и задать один конкретный вопрос.
- **«Сейчас не до этого»** — спросить прямо: «через месяц написать или совсем
  закрыть?». Прямой вопрос получает ответ.
- **«Не интересно»** — `status lost`, без уговоров. Через полгода можно вернуться.

## Как это связано с сайтом

Ссылка в сообщении собирается с UTM-меткой, в которую зашит id лида:

```
…/es?utm_source=instagram&utm_medium=dm&utm_campaign=barbers-bcn&utm_content=barberia-bk-sant-antoni
```

Сайт уже умеет это читать и класть в письмо с заявкой (см. «Campaign
attribution» в корневом README). Поэтому когда придёт заявка, в письме будет
написано, из какого именно барбершопа она пришла — и лида можно закрыть в
`won`, ничего не угадывая.

## Файлы

| Файл | Что это |
| --- | --- |
| `cli.mjs` | все команды трекера |
| `lib/store.mjs` | чтение и запись списка, модель лида |
| `lib/pipeline.mjs` | статусы, ритм касаний, кто «горит» сегодня |
| `lib/messages.mjs` | сборка сообщения, UTM-ссылка, счётчик скидочных мест |
| `templates/es.mjs` | **все испанские тексты** — правь здесь |
| `scripts/harvest-places.mjs` | сбор лидов из Google Places по районам |
| `scripts/audit-sites.mjs` | аудит сайтов → конкретный повод написать |
| `scripts/make-mockup.mjs` | макет главной их барбершопа + скриншоты |
| `scripts/fetch-fonts.mjs` | кэш шрифтов, чтобы макет был самодостаточным |
| `mockup/template.mjs` | **дизайн макета** — разметка и стили |
| `mockup/theme.mjs` | три палитры: brass / bone / ember |
| `mockup/demo.json` | заполненный пример макета |
| `data/leads.json` | живой список (не коммитится) |
| `data/seed-barcelona.json` | стартовая разведка, непроверенная |

Тексты живут в одном файле не для красоты: когда после тридцати сообщений
станет видно, что первая строка не работает, менять её надо в одном месте — и
следующие тридцать уйдут уже с новой.
